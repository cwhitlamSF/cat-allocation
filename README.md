# Cat Cost Allocation (CCA)

Allocates the upfront premium of the upper cat layers to individual policies, from RMS ELTs,
without simulation. Policy losses are moved to a net of per-risk and net of inuring basis (lower
towers, the FHCF proxy). Each upper layer's premium is then spread over events with a
distortion-calibrated key (Wang by default, on an occurrence or aggregate basis), and each event's
share is split across its policies.

It runs on the same platform as RSA and DTX: `shared-lib/main.py`, `_analysis.py`, `config_creator`
and the spec reader are shared, and this tool supplies its own `config.py`, `CCA_Functions.py` and
the engine package `catalloc/`.

## Files

                            the policy split within an event

  CCA_ConfigSpecs.xlsx      spec definitions (Tbl_specDefinition, Tbl_dataInputSpecs, Tbl_specDataFormats)
  CCA_Template.xlsm         the input workbook, empty, with the VBA
  CCA_Example.xlsm          the template filled in for the sample data (Prepare Data and five runs)

## Setup

1. **Packages:** `pip install -r requirements.txt`. **Keep Polars below 2.0**, because shared-lib's spec
   reader fails on 2.0.
2. **Workbooks.** Change table layouts in `cca_tables.py`, then run
   `python tools/build_workbooks.py --example`. The spec workbook and template are always generated
   together, so they can't drift apart. The VBA project in `vba/vbaProject.bin` is copied in, so the
   rebuilt `.xlsm` workbooks keep the Run macro. After changing the VBA in Excel (in
   `CCA_Template.xlsm`), save it back with `python tools/build_workbooks.py --save-vba CCA_Template.xlsm`.
3. **Config.** After any table change, run `shared-lib/config_creator/config_creator.py` and choose
   `CCA_ConfigSpecs.xlsx`. It writes `CCA_config.ini`, which tells the spec reader which tables to read.
   An out-of-date config makes new tables or columns invisible to the run.
4. **The VBA project needs the xlwings module** (the one with `RunFrozenPython`), as RSA's and DTX's do.
   Import it in Excel (export it from the RSA workbook, or `xlwings quickstart --standalone`), then save
   the project back as in step 2. Add a Run button on the Home sheet, assigned to `RunModel`, and set the
   exe path on the Model Path sheet (named cell `_executablepath`).

## Running

- **From Excel:** click Run. The exe reads the open workbook. Progress shows in the status bar
  (file by file during the allocation). Problems go to the Data Issues sheet. Results fill the
  Layer Summary, LOB Summary, Diagnostics, Benchmark and Output Log sheets, and a message box
  summarises the run.
- **From the exe:** choose "Run Analysis on Closed Excel File" and pick the workbook. It's read with
  calamine, so Excel isn't needed. The result sheets are written into the file afterwards (only the
  table rows change; VBA and buttons survive).

One Run does, in order:

1. **Prepare Data**, if Run Prepare Data is TRUE on the Prepare Data sheet. This needs doing once per
   RMS run. It reads the raw policy ELT (Parquet chunks in any grouping, or a database query) and
   writes event-grouped files (`ev_bucket_0000.parquet`, ...) to the Policy ELT Folder, so that every
   event's rows are in one file. Existing `ev_bucket` files in that folder are replaced. Column names
   are matched without regard to case; Column Renames handles others. IDs are stored as Int32 when they
   fit, and values as Float32. Set it back to FALSE once the files are built.
2. **Every row of Specify Runs with Include = TRUE.** The data and the programme tables are read once
   for all runs. The lookups (per-risk ratios, inuring towers, each layer's calibrated event weights:
   about a minute for HU, longer for SCS) are built once per distinct combination of Distortion, Basis,
   Inuring Sharing, Include Reinstatement Premium and Grid Points. So runs that differ only in Policy
   Split, Bounded Split or Clamp Negatives share them. Each run then goes through the event-grouped
   files in one pass, with nothing written to disk.

A run that fails is marked on the Run Summary sheet, and the other runs still finish. The run as a
whole then reports the failures at the end.

**Run every peril the towers cover together:** the BU ELTs and the policy ELT files should include
HU, SCS and any others. A layer's OEP, its annual loss and its premium are across all perils.

## The input tables

**General** (settings): Output Folder (each run writes to its own subfolder), Policy ELT Folder and
File Pattern, Policy ELT Is Net Of Per-Risk, Notes.

**Prepare Data** (settings): Run Prepare Data (TRUE/FALSE), Source Type (Parquet Files or Database
Query), Input Folder and File Pattern, or Connection and Query; Target Rows Per File; Column Renames.

**Specify Runs:** one row per run.

| Column | Values | Default |
|---|---|---|
| Run Name | required, unique; also its output subfolder, so no `\ / : * ? " < > \|` | |
| Include | TRUE / FALSE | TRUE |
| Distortion | wang, ph, identity (expected-loss key) | wang |
| Basis | occurrence, aggregate | occurrence |
| Inuring Sharing | conditional (co-recovery), prorata | conditional |
| Policy Split | conditional, mean | conditional |
| Bounded Split | TRUE / FALSE: no negative policy shares | TRUE |
| Clamp Negatives | TRUE / FALSE: the alternative fix | FALSE |
| Include Reinstatement Premium | TRUE / FALSE (aggregate basis) | TRUE |
| Benchmark Comparison | TRUE / FALSE: expected-loss keys and AAL share; about 3x the run time | FALSE |
| Grid Points | 50 to 20,000 | 500 |

A Basis or Distortion entered on an Upper Layers row overrides the run's setting for that layer, in
every run.

**Data Sources:** one row per dataset. Names are matched without regard to case; use Column Renames
(`PolicyID=POLICYID`) for others.

| Dataset | Columns |
|---|---|
| BU ELT Gross | EVENTID, LOBNAME, REGION (or COUNTRY + STATE), RATE, PERSPVALUE, STDDEVI, STDDEVC, EXPVALUE |
| BU ELT Net | the same, net of per-risk |
| Exposure | POLICYID, REGION (or COUNTRY + STATE), TIV. Only needed if a subject lists regions. |
| Policy LOB | POLICYID, LOBNAME. Repeated rows are fine, so the exposure table can serve. |

Source types: Parquet (a file, a folder or a wildcard), CSV, Excel Table, Database Query (SQLAlchemy URL;
`${VAR}` is filled from an environment variable, so no password sits in the workbook).

If the policy ELT is already net of per-risk, set Policy ELT Is Net Of Per-Risk to TRUE. The BU ELT
Net is then used for both, so per-risk isn't taken off twice. BU ELT Gross isn't needed then.

**Subjects:** one row per subject × LOB. A blank LOB means every LOB, and blank Regions means every
region. Regions are `COUNTRY_STATE` codes, comma-separated. Don't list all regions: leave the cell
blank. Listing regions makes the LOB region-sensitive, which needs exposure data.

**Inuring Layers:** Stage (order; same stage and subject = one tower), Layer, Retention, Limit,
Placement (a fraction), Subject, Multiple Regions Per Policy (FALSE: each policy just takes its
region, no split), Include.

**Upper Layers:** Layer, Retention, Limit, Subject, Premium (100%), Placement (a fraction; Premium ×
Placement is allocated), and optional Basis, Reinstatements, Reinstatement Rate, Agg Limit, Agg
Deductible, Distortion, Theta, Multiple Regions Per Policy, Include.

Placement is called **Placement** in the workbook, not "Placement %": the platform's config reader
treats `%` as special. (See "shared-lib note" below.)

## Results

On the workbook, each with a Run Name column so runs can be compared side by side (filter, or pivot
on Run Name):
- **Run Summary:** one row per run (and Prepare Data): ok or failed, its settings, the placed premium,
  the amount allocated, policies, run time, and the error for a failed run.
- **Layer Summary:** per run and layer, the basis, distortion and its parameter, premium terms,
  calibration target, expected loss, load, P(attach), P(exhaust), aggregate terms, amount allocated,
  policies, events, bounded rows, and the negative share before the bound or clamp.
- **LOB Summary:** premium and share of layer by run, LOB and layer, plus all layers.
- **Diagnostics:** per run, rows read and dropped (no LOB, no exposure), region splits and fallbacks,
  events spanning files, and the **policies / cells check**. For each layer, it gives the median ratio
  of the policies' net mean to the BU × region net mean, over the events in the first file, which
  should be close to 1. Then the total allocated. Prepare Data adds files, rows and events written.
- **Benchmark** (runs with it switched on): by LOB, the gross AAL share, the expected-loss key with
  mean and conditional splits, and the final allocation, all scaled to the same total.
- **Output Log:** every file written.

In the output folder, there's a subfolder per run with `premium_by_policy_layer` and
`premium_by_policy` (Parquet and CSV) and the summary tables as CSV. With more than one run,
`premium_by_policy_all_runs.parquet` has one column per run.

## Checks

Before reading any data, the run checks the tables and stops with a list of every problem it finds:
- runs with no name, duplicate names (case is ignored) or names that can't be folder names;
- unknown distortions, bases, sharing rules, splits or source types;
- unreadable TRUE/FALSE values (these columns are read as text so a typo is caught, not defaulted);
- missing files and folders, or no files matching the pattern (unless Prepare Data runs first);
- missing datasets (Exposure when a subject lists regions; BU ELT Gross unless the policy ELT is net);
- layers naming a subject that doesn't exist, or layer names used twice;
- a placement outside (0, 1], so 90 instead of 0.9 is caught;
- a premium that isn't positive, or a negative or fractional number of reinstatements;
- nothing to do (no runs included and Prepare Data off).

Problems that depend on the data are reported on the Data Issues sheet without stopping the run:
- LOBs in the policy map but not in the BU ELT;
- subject LOBs or regions not in the BU ELT;
- rows dropped for no LOB or no exposure;
- policies flagged single-region that span regions;
- events spanning files;
- a policies / cells ratio more than 5% off;
- layer totals not tying to the calibration target.

## The exe (PyInstaller)

As for RSA and DTX:
- **Data files:** bundle `CCA_config.ini`.
- **Hidden imports:** add `CCA_Functions`, `cca_tables` and the `catalloc` modules (`_analysis`
  imports the hooks by name, so PyInstaller can't see them), and also `scipy.special`.
- **Optional:** add `sqlalchemy` and the database driver if Database Query is used.

The calibration uses threads (scipy's incomplete beta releases the GIL), which works the same in the
frozen exe.

## Tests

`python tests/run_all.py` runs:
- **Engine tests:** identity distortion = expected loss; Wang/PH parameters and event weights against
  Monte Carlo; the aggregate basis against 1M simulated years; the chunked driver against the
  in-memory calculation; the bounded split; Prepare Data.
- **End-to-end test:** through `main.main()` on the example workbook. It runs Prepare Data and five runs
  in one click, with each run compared to the engine called directly, and checks that lookups are
  shared. It also runs with one run made to fail (the others finish), and a workbook with planted
  mistakes.

## shared-lib note

`config_creator` and `modelkit.specs.configparser_to_dict` use `configparser.ConfigParser()` with
its default interpolation, so any `%` in a spec table's column name or value fails. Passing
`interpolation=None` in both places would fix it. That's a shared-lib change, so it isn't made here.
